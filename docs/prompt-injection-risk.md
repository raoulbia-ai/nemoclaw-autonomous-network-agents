# Prompt Injection Risk Assessment

*Last updated: 2026-04-09*

## TL;DR

In the **current sandbox-only setup, prompt injection risk is low** because
every byte the agents see comes from a deterministic mock network under
`network/ireland/`. There is no untrusted external data source.

The risk **becomes real the moment any agent ingests data from outside the
mock** — a real CM/PM feed, a web fetch, an RSS pull, an email, a ticketing
API. The 2025-2026 literature is unanimous: any data an LLM agent reads
becomes part of its control plane.

## Why the risk is currently low

- The "network" is generated by your own code (`alarm-generator.js`,
  `pm-generator.js`, `data-ireland.js`). Alarm descriptions, fault types,
  and result strings are not attacker-influenced.
- Agents only have file/HTTP tools pointed at the local mock server. No
  web browsing, no MCP tool that fetches arbitrary URLs, no email/Slack
  ingest.
- Remediation actions are constrained to a small enum (`clear-alarm`,
  `restart-cell`) validated server-side at `network/server.js:210-212`.

## Where it would become a real risk

1. **Real telemetry feed.** If `data-ireland.js` is ever swapped for a
   real CM/PM source, alarm `additionalText` and event metadata become
   attacker-influenced. SENTINEL passes these through to the LLM verbatim
   in the SENTINEL → ORACLE handoff.
2. **External context fetcher.** `update-external-context.js` — if it
   ever pulls from RSS, web, or a ticketing system, each fetched blob is
   a prompt-injection vector. See the
   [Log-To-Leak paper](https://openreview.net/forum?id=UVgbFuXPaO) for a
   working demo against tool-using agents.
3. **Bulletin board cross-contamination.** `agent-comms.jsonl` is
   read-by-LLM and the agents currently run with `/elevated full` (see
   CLAUDE.md). A compromised single agent could plant instructions for
   the next agent — there is no provenance separation between
   agent-authored content and "trusted" prompt content.
4. **Mock auth on the network server.** `network/server.js:117-120`
   accepts any Bearer token. Fine for the sandbox, but if an injected
   instruction ever convinced an agent to call a different `baseUrl`,
   the agent would trust whatever responded.

## Defensive actions before any "real data" pivot

- **Wrap external tool outputs in a delimited block** (e.g.
  `<tool-output>...</tool-output>`) and instruct the agent in its system
  prompt to treat the contents as data, never instructions.
- **Sanitize free-text fields** — strip control characters and known
  injection markers from `alarm.additionalText` and similar fields
  before agents see them.
- **Tighten `/elevated full`.** Move to per-tool allow-lists so a
  compromised agent cannot pivot to arbitrary shell or filesystem
  access.
- **Add provenance to `agent-comms.jsonl` entries** (signed-by,
  action-type). Readers should refuse to follow imperatives from
  unsigned posts.
- **Pin `baseUrl`** at the openshell provider layer so an injected
  instruction cannot redirect inference to an attacker-controlled
  endpoint.
